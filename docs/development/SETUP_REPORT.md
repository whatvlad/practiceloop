## Independent review

Отдельный агент Codex проверил существовавшие на момент первого review CI,
защиту ветки, SQL/RLS, скрипты, backend, frontend и правила работы. Существенных
замечаний по этому объёму не выявлено. Он независимо выполнил frontend-проверки,
backend lint/types и 65 математических тестов. Его HTTP-тесты остановились до
входа в приложение из-за ограничения Windows socket-pair в sandbox. Основной
агент успешно повторил все 67 тестов вне ограничения и в Linux.

Это отдельный Codex, а не Claude Code и не человеческое одобрение. Для позднее
добавленных инструкций публикации и задач выполнен повторный review. Он выявил
два замечания средней важности: чтение UTF-8 в PowerShell 5.1 портило π/√ в
публикуемых задачах, а критерий PL-003 неявно зависел от PL-004, которая сама
зависела от PL-003. Исправлены явным UTF-8 и разделением критериев схемы/API;
локальные проверки исправлений успешны. Review опубликованного PR пока невозможен.

проверить независимое человеческое одобрение остаётся у людей.

## Задачи, роли и следующие действия

[15 задач MVP с критериями, приоритетами и зависимостями](BACKLOG.md).
Все локальные, без владельцев и GitHub-номеров. Начать с PL-001 (GitHub) и PL-002
(контракты и открытые решения), затем Supabase/Auth и ограниченный генератор,
после — UI и история, end-to-end проверки и deployment. PL-009 разделить по темам.

Предложено: Developer 1 + Codex — frontend/KaTeX/сценарии; Developer 2 + Claude
Code — API/SymPy/Supabase. Агенты взаимно проверяют код, люди независимо одобряют.
[Подключение второго разработчика и запуск обоих агентов](ONBOARDING.md).

Синхронизация: отдельные clones/worktrees -> fetch -> осмысленное обновление
ветки -> push -> PR -> CI/review -> человеческий merge -> fetch другого участника.
Локальные Markdown-файлы не синхронизируют компьютеры и не блокируют задачи.
GitHub станет главным источником истины только после публикации.
